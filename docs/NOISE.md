# Noise Robustness Scorecard

本番経路 (LID→ルーティング→デコード→ja句読点) を、クリーン音声と white/pink/babble ノイズ (SNR 20/10/5/0dB) を重ねた音声の両方で評価。metricは en=WER, 他=CER（yueはt2s正規化）。

## ノイズ生成条件

- SNRは対象音声のRMSパワー基準: `10*log10(P_speech/P_noise) == SNR_dB`
- noise種別: white（ホワイトノイズ）, pink（1/fピンクノイズ）, babble（同一プールの別言語クリップを2〜3本ランダムに重ねた話し声ノイズ、対象と同言語は使用しない）
- SNRレベル: 20, 10, 5, 0 dB
- 乱数seed: 42（固定・再現可能、`scripts/make_noisyset.py` 参照）
- クリッピング防止: 混合波形のピークが1.0を超える場合は全体をスケールダウン
- 生成スクリプト: `scripts/make_noisyset.py` / 評価スクリプト: `scripts/eval_noise.py`

### 結論

ノイズ条件 60件中、denoiseでerrが改善したのは4件、悪化したのは52件、ほぼ変化なしが4件（平均Δerr=-0.099、正=改善）。 クリーン音声側の副作用: 平均Δerr=-0.038（悪化＝デノイザが健全な音声に悪影響）。 LIDは26件で悪化、3件で改善。 GTCRN自体のRTFは平均0.051と軽量。

**不採用が妥当**: ノイズ条件でも改善より悪化が多く、クリーン音声にも悪影響が出ている。前処理として常時オンにする根拠がない。

## LID頑健化: sticky-LID ヒステリシス

### 崩壊メカニズム

`scripts/asr_engine.py` の `RoutedASR.transcribe()` は、セグメントごとに whisper-tiny ベースの
`SpokenLanguageIdentification` を1回呼んで言語タグを取得するだけで、確信度（confidence/logprob）は
sherpa-onnx の Python API 上に存在しない（`SpokenLanguageIdentification.compute()` は言語コードの
文字列しか返さない）。改修前のコードには「2秒未満の短い発話が直前と違う言語を叩いたら、2回連続で
同じ新言語が出るまでセッション言語を維持する」というヒステリシスが既にあったが、これは
`speech_s < min_switch_s(=2.0)` の場合限定で、ジングル/SFXの誤爆対策として作られたもの
（`docs/VIDEO_TEST.md`）。通常長（2秒以上）のセグメントは単発のLID結果をそのまま採用しており、
babbleノイズ下ではこの「長いセグメントは信頼できる」という前提が崩れる: 4秒ウィンドウ全体に別言語の
話し声が重なっていると、whisper-tiny LIDはセグメント長によらず単発で誤爆し得る。誤爆すると
ルーティング先の専用モデル（ReazonSpeech/Paraformer/SenseVoice/v3/Omni）ごと変わってしまい、
そのセグメントのerrが跳ね上がる。セグメント間の状態保持は `last_lang`（直近の確定言語）のみで、
確信度に基づく重み付けは元から無かった。

### 採用ポリシー: 非対称ヒステリシス（sticky LID）

確信度が取得できないため、**多数決/時間窓平滑化ではなく、連続確認によるヒステリシス**を採用した
（`scripts/asr_engine.py` の `resolve_sticky_lang()` に切り出し、`RoutedASR.transcribe()` から呼ぶ）。

- セッションの直前確定言語（`last_lang`）と異なる言語が検出されても、**即座には切り替えない**。
- 同じ新言語が `lid_switch_confirm`（デフォルト **2**）回連続で検出されて初めて切り替える。
- 直前言語を維持する側には確認は不要（非対称）: ノイズがセッションを誤った言語に固定できないようにする。
- 短い発話（`speech_s < min_switch_s`）での保留は、旧来どおりomniフォールバックを抑制する
  （ジングル/SFXの空デコードをomniが「復活」させないため）。それ以外（長い発話の保留）はomni
  フォールバックを許可する — 保留は「本物の音声だが違う階層のモデルで無理にデコードした」だけの
  可能性が高く、そのモデルが空を返したら1600言語汎用モデルに賭ける方が良いため。
- 汎用性: 制約は `speech_s` によるヒステリシス発動条件そのものではなく、旧来 `min_switch_s`
  未満の発話に限定されていたヒステリシスをすべての発話長に一般化した点。クリーン音声で言語が
  実際に切り替わる場合は最大 `lid_switch_confirm - 1` セグメント（デフォルト1セグメント）の遅延で
  切り替わる。

コンストラクタ引数 `lid_switch_confirm: int = 2` として公開（`RoutedASR.__init__`）。

評価用の注意点: `scripts/eval_noise.py` の評価セットは「言語ごとに独立収録されたクリップを
連続して流す」構成（例: babbleの1条件マニフェストは ja→en→zh→ko→yueの順で12〜15本ずつ連続する）。
これはRoutedASRの視点では別々の無関係な録音であり、1つの継続セッションではない。そのため
`RoutedASR.reset_session()`（新規追加）を各言語ブロックの先頭で呼び、直前の無関係な言語からの
「切り替え」としてヒステリシスが誤って発動しないようにしている（`eval_manifest_dir()` に実装）。
実セッション内の応答性（本物の言語切り替え）は `tests/test_units.py` の
`resolve_sticky_lang` 系ユニットテストで別途担保している。

### 結論

- **クリーン回帰ゼロを確認**: 5言語すべての clean 条件で LID正解率・errとも完全一致（Δerr=+0.000）。
  当初の実測では ko/yue の clean で大きな悪化が出たが、これは評価ハーネスが複数言語のクリップを
  同一 `RoutedASR` セッションで連続再生していたための計測アーティファクト（言語ブロック境界で
  「セッション内の言語切り替え」とみなされ1クリップ分保留されていた）で、`reset_session()` を
  各言語ブロックの先頭に挿入して解消した。
- clean以外の対象40条件（5言語 × white5/white0/pink5/pink0/babble20/10/5/0）中、
  **LID正解率が改善したのは15条件、悪化したのは2条件、残り23条件は変化なし**。err も概ね連動して改善。
  特にko(babble snr=0: 8/12→12/12, err -0.194)、zh(babble snr=0: 5/12→8/12, err -0.131)、
  ja(white snr=0: 7/15→13/15, err -0.288)で大きな改善。
- **悪化した2条件（ともにsnr=0dBの極限条件）**: ja babble snr=0dB（LID 3/15→1/15、err
  +0.012とわずか）と yue babble snr=0dB（LID 8/12→5/12、err +0.097）。原因は非対称ヒステリシスの
  裏返し: 単発の誤爆には強くなった代わりに、SNR=0dB（ノイズ電力=音声電力）というLID自体がほぼ
  当てにならない極限状況で、たまたま2クリップ連続で同じ誤った言語が出ると、そちらに「確定」して
  しまい、そこから抜けるのにまた2連続の正解が要る。つまりヒステリシスは「単発の揺らぎ」には
  効くが「持続的なほぼ50/50の誤判定」には裏目に出ることがある。severity最上位のsnr=0dBでのみ
  発生しており、より現実的なsnr=5/10/20dBでは一貫して改善または変化なし。
- **総合判断**: 採用が妥当。ほぼすべての条件で改善または無変化、悪化は2件のみで最も過酷な
  snr=0dB条件に限られ、かつ影響は小さい（err差 +0.012 / +0.097）。クリーン音声での言語切り替え
  応答性は最大1セグメントの遅延に抑えられており（`lid_switch_confirm=2`）、
  `tests/test_units.py` の `resolve_sticky_lang` 系テストで retained。
